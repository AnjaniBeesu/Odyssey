================================================================================
ODYSSEY - OPEN SOURCE ISSUE SUGGESTIONS & LABELING STRATEGY
================================================================================

Suggested GitHub Labels Taxonomy:
----------------------------------
- Difficulty Levels:
  * `level-1` (or `good first issue` / `beginner-friendly`)
  * `level-2` (or `intermediate` / `enhancement`)
  * `level-3` (or `advanced` / `core-architecture`)
- Type Labels:
  * `type: bug`
  * `type: feature`
  * `type: documentation`
  * `type: tooling` / `type: devops`
  * `type: a11y` (Accessibility)
- Domain / Area:
  * `area: frontend`
  * `area: timer`
  * `area: gamification`
  * `area: storage-sync`
  * `area: testing`

================================================================================
Goal: Simple fixes, markdown/docs, lightweight UI additions, styling polish, zero or minimal backend setup needed.

---
ISSUE #1
Title: feat(theme): Support system theme preference detection & smooth transition
Labels: level-1, good first issue, type: feature, area: frontend
Description:
  Currently, `useTheme.tsx` checks `localStorage` for a theme, but if no saved theme exists, it defaults directly without checking the user's OS preference (`prefers-color-scheme`).
  
  Tasks:
  1. Update `src/hooks/useTheme.tsx` to inspect `window.matchMedia('(prefers-color-scheme: dark)').matches` when no saved preference exists in `localStorage`.
  2. Listen for OS theme change events (`change` event on `matchMedia`) so if the user has not manually overridden their theme, Odyssey adapts dynamically.
  3. Verify that `ThemeToggle.tsx` reflects the updated theme state cleanly.
  
  Skills required: React, CSS/Browser APIs, TypeScript.

LEVEL 3 ISSUES (Advanced / Core Architecture / Performance / Offline Sync)
================================================================================
Goal: Complex architectural enhancements, local-first offline synchronization, AI streaming, and PWA capabilities.

---
ISSUE #9
Title: feat: Local-first offline sync & conflict resolution with Supabase
Labels: level-3, type: feature, area: storage-sync, area: core-architecture
Description:
  Currently, Odyssey switches between `localStorage` (guest) and Supabase (signed in). When an anonymous user decides to sign up / log in, or when a logged-in user goes offline, changes can get desynchronized or wiped out.
  
  Tasks:
  1. Build an automatic data migration utility that seamlessly migrates all guest `localStorage` tasks and sessions into Supabase upon first sign-in.
  2. Introduce an offline queue (e.g. IndexedDB or queued localStorage mutation events) that records mutations when offline and syncs them up to Supabase when `navigator.onLine` returns true.
  3. Implement last-write-wins or timestamp-based conflict resolution.
  
  Skills required: Supabase, IndexedDB / Storage architecture, Offline web patterns.

---
ISSUE #10
Title: feat: Convert Odyssey into an installable PWA with Service Worker & Background Timer
Labels: level-3, type: feature, area: core-architecture, area: timer
Description:
  Users want Odyssey as a standalone desktop or mobile application so they can keep their focus timer running without keeping a full browser window visible.
  
  Tasks:
  1. Configure `vite-plugin-pwa` to generate a manifest, icons, and service worker.
  2. Cache core app shell and static assets for full offline startup.
  3. Implement a Web Worker for timer tracking so throttling in background tabs doesn't drift or freeze elapsed seconds.
  4. Enable PWA install prompt button in navigation for supported browsers.
  
  Skills required: Progressive Web Apps (PWA), Service Workers, Web Workers, Vite.

---
ISSUE #11
Title: feat: Streaming AI responses & interactive clarification loop for Capture
Labels: level-3, type: feature, area: core-architecture, area: frontend
Description:
  Currently, capture interpretation (`interpretCapture` in `src/services/aiService.ts`) calls Gemini via a Supabase Edge Function in a single blocking request. If the user's prompt is ambiguous, the model makes static assumptions.
  
  Tasks:
  1. Update Edge Function and client service to support Server-Sent Events (SSE) streaming for real-time item parsing feedback.
  2. Add an interactive clarification card when ambiguous tasks are detected (e.g. Gemini suggests: "Did you mean submit tax documents or just gather receipts?").
  3. Add optimistic UI updates so raw inputs are instantly reflected in a draft state while the AI finishes refinement.
  
  Skills required: Server-Sent Events (SSE) / Streaming, Gemini API / Edge Functions, Advanced React state.
